## Composition

`DataViewProvider` holds the view state and toolbar state for one data view. It renders no markup of its own, so you own the layout. Put toolbars anywhere inside it, and wrap the view in `DataViewContent`, which runs the controller queries.

```tsx
import { DataViewContent, DataViewProvider, usePageController } from "@sparkyidea/dataview-react";
import { useNuqsDataViewState } from "@sparkyidea/dataview-react/nuqs";

const state = useNuqsDataViewState();

<DataViewProvider
  controller={controller}
  defaults={{ limit: 25, sort: [] }}
  properties={productProperties}
  state={state}
>
  <div className="flex flex-col gap-2">
    <NotionToolbar enableSettings />
    <DataViewContent>
      <TableView pagination="page" />
    </DataViewContent>
  </div>
</DataViewProvider>
```

`DataViewContent` suspends while the first page loads. Toolbars outside it keep rendering. Wrap the provider in a `Suspense` boundary with a skeleton fallback (see [Table View](/docs/data-view/views/table#loading-state)).

`BoardView` needs an infinite controller (`useInfiniteController`) and throws when given a page controller.

## Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `controller` | `PageController \| InfiniteController` | - | From `usePageController` or `useInfiniteController` |
| `properties` | `DataViewProperty[]` | - | Property schema |
| `defaults` | `DefaultsConfig` | - | Values used when the URL has no matching parameter. `limit` defaults to 25 |
| `state` | `DataViewStateAdapter` | in-memory | Where filter, sort, group, search, limit, and cursors live |
| `propertyVisibility` | `string[]` | all | Visible property IDs |

## State

Without a `state` prop the provider keeps its state in memory. Pass `useNuqsDataViewState()` to keep it in the URL (requires `nuqs` and its adapter), or pass your own `DataViewStateAdapter` for controlled state:

```ts
interface DataViewStateAdapter {
  value: DataViewState;
  onChange: (update: (previous: DataViewState) => DataViewState) => void;
  isPending?: boolean;
}
```

`DataViewState` holds raw `column`, `cursors`, `filter`, `group`, `limit`, `search`, and `sort`. `null` means "not set" and falls back to `defaults`. The provider validates values against `properties` and resets cursors when the query changes.

## Several views on one page

Each provider keeps its own toolbar state (open filter and sort popovers, chip row). With URL state, give each view a distinct `urlPrefix` so their parameters do not collide:

```tsx
const orders = useNuqsDataViewState({ urlPrefix: "orders." });
const returns = useNuqsDataViewState({ urlPrefix: "returns." });
```

This gives URLs like `?orders.filter=…&returns.sort=…`. On the server, pass the same prefix to the params cache:

```ts
import { createDataViewParamsCache } from "@sparkyidea/dataview-react/nuqs/server";

const ordersParams = createDataViewParamsCache({ urlPrefix: "orders." });
```

## Images

Cards and the files & media property render images with a plain `<img>`. To use a framework image component, such as `next/image`, wrap your app in `DataViewImageProvider`:

```tsx
import { DataViewImageProvider } from "@sparkyidea/dataview-ui/image";

<DataViewImageProvider component={MyImage}>{children}</DataViewImageProvider>
```

`MyImage` receives standard `<img>` props (`src`, `alt`, `className`, `loading`, `sizes`, `onLoad`) and sizes itself with the classes it is given.
